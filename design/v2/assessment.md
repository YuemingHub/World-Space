# existing-web 评估（RUN_DIRECTORY: .ohmyagent/design/v2）

## 现状
- v1 原型（.ohmyagent/design/v1/prototype.html，sha256 前缀 9130bb4b）已过 design-jury R2（8.0/10，passed）与渲染质量门（89/100，passed）。
- 视觉权威：Storytelling 模板 DESIGN.md + v1/visual-foundations.md（tokens、字体、色彩纪律）。
- 结构：hero → 信念对比 → 引言带 → 故事卡 ×4 → 四步方法 → CTA → 页脚。

## 用户新定位（本轮变更动因）
网站是一条转化路径：**看见 → 学会 → 陪跑**。
1. 看见：让人知道 AI 能做什么（对应现有故事区，保留）。
2. 学会：提供非常细致的教程，让人能自己学、自己搞出作品（现有"四步方法"太浅，需升级为真正可跟做的细致教程——本轮核心工作量）。
3. 陪跑：引导需要帮助的人申请陪跑，**直到完成第一个自己想要的作品**（新增转化区）。

## 变更范围（bounded refinement，保留视觉方向）
- 保留：视觉方向、tokens、字体、色彩、既有故事区与信念区内容、无障碍基线。
- 修改：信息架构由"故事→方法"升级为"看见→学会→陪跑"三幕；导航与 CTA 链路随之调整（主转化 = 申请陪跑）。
- 新增：①细致教程区（以一条完整可跟做的"第一件作品"路径为主轴 + 其他作品路径索引）；②陪跑区（陪跑给什么、怎么陪、完成后什么样 + 申请 CTA 占位）。
- 占位声明：陪跑联系方式（微信/表单）、真实课程链接由用户提供，页面明示占位；教程示例 prompts 为示意内容。
- 不做：不虚构价格、效果承诺、学员数据。

## 验收
- 三幕结构在视觉叙事上成立，导航/CTA 链路完整（看见→学会→陪跑→完成第一件作品）。
- 教程区细致可跟做：有阶段、有动作、有示例提示词、有"做完长什么样"的检查点。
- 既有无障碍与质量门标准维持；jury 与 quality gate 需重新通过。
