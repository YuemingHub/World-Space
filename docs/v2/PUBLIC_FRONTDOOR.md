# 公开门面页（未登录 `/`）

> 2026-09-25。产品决定（本轮已确认，不再重新讨论）：`https://ymai.fun/` 未登录时给公开 World Space 门面；已登录仍进 v2 应用。本文更新 `AUTH_UI_PREDEPLOY_HANDOFF.md` §2 接口清单中「GET /（保护，302 /login）」一条的行为，其余接口语义不变。

## 行为矩阵

| 请求 | 未登录 | 已登录 | 认证配置损坏（broken） | auth=off（仅本地开发） |
|---|---|---|---|---|
| `GET /`、`GET /index.html` | 200 公开门面 | 200 v2 应用 | 200 公开门面 | 200 v2 应用 |
| `GET /login` | 200 登录页 | 302 `/` | 200 登录页（如实说明未配置好） | 302 `/` |
| `POST /api/world` | 401 | 正常契约 | 503 fail closed | 正常 |
| `GET /api/auth/me` | 401 | 200 user_id | 503 | 200 local |
| 其余静态资源（/app.js 等） | 公开（只有代码，无用户内容） | 同左 | 同左 | 同左 |

不变量：**公开门面 ≠ 公开应用/API**。门面页是纯静态资产，不含任何用户数据、不调用任何接口；认证后端损坏时它照常显示，业务 API 照旧 fail closed。门面页 HTML 与登录后应用页同为 `no-store`。

## 文件与真源

- 运行时资产：`web/public-frontdoor/index.html`（`server/world.mjs` 经 `CFG.frontdoorDir` 提供，只挂在 `/` 与 `/index.html` 上；门面文件缺失时回落 302 `/login`，不裸 404）。
- 内容真源：**main 分支 `web/index.html`**（当前复制自 `d9d948f`）。main 门面更新后须重新复制到本文件并保留页脚「已有账号？登录」链接——这是本副本对真源的唯一差异（复制时点之后 main 的一切更新都不会自动到达这里，同步是人工责任，见文件头注释）。
- 门面资产目录与 `web/v2/`（登录后应用）物理分开：应用页代码不会混进门面，门面也不会在其它路径被直接取到（`GET /public-frontdoor/…` 不在静态根内，404）。

## 用户旅程

- 新访客：`/` → 门面页（选一件事，马上开始；页脚可去 `/login`）。
- 老用户：`/login` 登录 → `/` 应用页 → 退出 → `/` 回到门面页。会话过期（7 天）后回 `/` 看到的是门面页而非直接弹登录——页脚登录链接是入口。
