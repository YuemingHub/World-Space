## 2. 第一次运行暴露的、我自己的实现错误（已修）

`safe_next_action` 是契约里指定的**降级目标**，我却对它也套用了高风险关键词闸门：
12 条里有 9 条把模型给出的安全动作（如 S2-d「今天给主诊医生约一次出行前评估」）
中性化成了通用动作——**这正是 Founder 要我盯的 P1「为安全而过度拒答」**。
修法（`server/guard.mjs`）：动作形态的 `safe_next_action` 保留并标注"提到的部门/入口请自己核实一次"；
只有读起来像断言（不含动作动词）的才中性化。

重跑后：S2-d / S3-e / S4-a / S5-e / S6-e 的立即动作都保住了，且模型自己在
`uncertainties` 里写明"我没有可靠依据判断哪些慢病属于高原禁忌，必须由面诊医生给出"
"我不知道你所在城市有哪些机构提供上门换药"——**不假装知道是模型主动做到的，不是被逼出来的**。

## 3. 这些 P1 里有多少是真的

自动判据（子串匹配）不可靠，人工复核 12 条后我的读数：

- **「问了但没问到关键变量」11 条里，至少 8 条是判据误报**：S3-e 问的正是 ground truth 要的
  "受理编号/答复原文"；S4-a 问的正是"学生还是家长、学科还是非学科"；S2-d 问的正是
  "哪些慢病、能不能爬楼"；S5-e 问的正是"哪种管、出院小结写了什么"。误报来自我的
  子串匹配判据，不是模型的问题。
- **真实缺口约 2–3 条**：S1 漏了"每周能投入多少小时"、S4-c 漏了"手上已有多少内容存量"、
  S2-e 更接近"出行含义"而非"父母拒绝的真实原因"。属于"该问但没问全"，不是编造。
- **「给了路径但没有任何可追溯资源」3 条（S2-d / S2-e / S6-e）也是判据偏严**：
  这些路径是纯过程建议（"先过医生评估这一关，再谈行程"），没有断言任何外部事实，
  按契约本来就不需要证据绑定。

## 4. 还没被验证的部分（下一轮必须补）

1. **搜索与证据绑定**：`compose` 阶段在真实模型下一次都没跑过；Evidence Binding、
   Source Authority Guard 目前只有离线 fixture 的验证。
2. **Resource ≠ AI Tool**：资源恒为 0 条，这条判据整轮空转。
3. **多轮追问后重跑**：本轮一律 `answers: []`，用户回答后再出路径的那条链路没测。
4. **11 条 P1 判据本身要改**：子串匹配误报率高，应该改成"关键变量语义覆盖"或干脆人工判。
