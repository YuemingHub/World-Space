# ARCHITECTURE DECISION — V2 最小架构

> 状态：**待 Founder 拍板**（2026-09-12）。本文件只做比较与推荐，不含施工。
> 依据：`NORTH_STAR.md`（内核）+ `REALITY_PRESSURE_SET.md`（6 个真实意图的实测压力集）。

## 0. 架构必须回答的问题

一个普通人用一句模糊的真话进来说"我想……"，架构要能：

1. 听懂他真正要做成什么（而不是他字面说的东西）；
2. 判断缺哪些现实事实、并**反问**；
3. 找到世界里真实存在的资源（人 / 机构 / 政府 / 服务 / 地点 / 开源 / AI / 商品）；
4. 给出**可点开来源**的默认路径与今天的第一步；
5. 允许他做完之后把世界的结果带回来，并据此调整下一步。

**判定前提**：V1 的"0 后端 / 0 外部请求"是那一版的实现选择。本文件**不默认沿用**它。

## 1. 候选定义

| 代号 | 方案 | 一句话 |
|---|---|---|
| **A** | 纯静态预制场景 | 页面预置"意图 → 资源"映射表，靠选择或关键词匹配；没有智能层 |
| **B** | 浏览器端跳转外部 AI | 页面把意图交给用户自己的豆包 / DeepSeek（结构化模板 + 引导），用户自己跟 AI 对话 |
| **C** | 极薄 serverless 智能层 | 页面调用**一个**我们自己的接口；接口内复用现成 LLM API + 现成搜索 API；返回结构化结果 |
| **D1** | 复用现成智能体平台 | 在扣子 / 阿里云百炼上零代码搭一个智能体，页面用官方 SDK 或接口调用它 |
| **D2** | 人工核验（concierge） | 用户提交意图，由 Founder 人工给出路径；页面只承载"提交 → 拿到路径" |

## 2. 十维度对比

| 维度 | A 纯静态 | B 跳外部 AI | **C 极薄智能层** | D1 现成平台 | D2 人工 |
|---|---|---|---|---|---|
| 处理开放真实意图 | ❌ 落不进格子 | ✅ | ✅ | ✅ | ✅ |
| 访问当前现实 | ❌ 构建时冻结 | ⚠️ 取决于用户用的 AI | ✅ 可接搜索 | ✅ 平台插件 | ✅ |
| 可引用真实来源 | ❌ 静态链接 | ❌ 拿不到结果 | ✅ 结构化 URL | ⚠️ 对话文本为主 | ✅ |
| 容易误指路 | ❌ 高（强行匹配） | ⚠️ 中（责任外移） | ⚠️ 可控（见 §4） | ⚠️ 中 | ✅ 最低 |
| 隐私 | ✅ 最好 | ✅ 好 | ⚠️ 意图出浏览器 | ⚠️ 意图进第三方 | ⚠️ 进 Founder 私聊 |
| 成本 | 0 | 0 | 🔸 约 0.02–0.06 元/次 | 🔸 免费额度起步 | 🔸 她的时间 |
| 维护复杂度 | ❌ 高（映射表会烂） | ✅ 低 | ⚠️ 中（一个接口 + 两个 key） | ✅ 最低 | ❌ 不可持续 |
| 中国普通用户可用 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 不造轮子 | ⚠️ 自己维护映射＝小轮子 | ✅ 最彻底 | ✅ 只写薄适配 | ✅ 最彻底 | ✅ |
| 换模型方便 | — | — | ✅ 改 base_url + model | ❌ 被平台绑定 | — |

**逐维度补充（关键几项）**

- **误指路的量级不同**：A 的误指路是"把不属于他的场景塞给他"（typed-door 实证 1/15 误指路）；
  C 的误指路是"模型编造一个不存在的机构"。两者都致命，但 C 可以用工程设计压下去（§4），
  A 的结构性缺陷无法用工程解决。
- **可引用来源是分水岭**：搜索结果 API（博查 / 阿里云联网搜索）返回的是 `title / url / snippet`，
  可以逐条点开；LLM 自带联网返回的是叙述文本，**无法逐条核验**。
  按 `NORTH_STAR.md` §4"引用必须能点开"，只有前者满足。
- **D1 的真实优势是"今天就能试"**：零代码、有免费额度、国内可用；真实劣势是**被平台绑定**，
  且我们难以强制"必须反问 / 必须给来源"这类硬约束的稳定输出格式。

## 3. 推荐（明确）

> **推荐 C 作为 V2 的最小架构（目标形态）。**
> **先用 D1 做零代码验证（Step 1），B 作为永久降级出口，A 只保留"静态兜底"角色。**
> **D2 不作为架构，但建议并行做 3–5 次人工核验，用来给 Step 1 定基准答案。**

理由，按内核优先级：

1. **只有 C 同时满足"理解开放意图"和"访问当前现实"**（压力集里三个月内就出现了三处时效性变化，
   静态必死）。
2. **只有 C 能给出可逐条点开的来源**，这是"不假装知道"唯一的技术兑现方式。
3. **C 是最低阻力的复用路径**：它不发明任何东西——模型用百炼（OpenAI 兼容，可直调、可换），
   搜索用现成 API，我们只写"一次文本进、一个结构化 JSON 出"的薄适配层，
   正是 `AGENTS.md` 复用优先级里的第 4 档。
4. **D1 先行是最省钱的验证**：如果现成平台搭出来的智能体能过 §8 的及格线，
   我们连那一个接口都不用写；过不了，再写 C，且此时我们已经知道**要写什么**。

### 3.1 C 的"极薄"量化边界（防止它长成平台）

| 项 | 上限 | 超了就违反内核 |
|---|---|---|
| 接口数量 | 1 个 | 出现第 2 个业务接口即需重新评审 |
| 代码量 | ≤ 200 行 | 超过就该问"是不是在自研引擎" |
| 状态 | 无数据库、无会话、无用户系统、无队列、无缓存层 | 任何持久化都要单独拍板 |
| 外部依赖 | 1 个 LLM API + 1 个搜索 API | 引第 3 个依赖要说明为什么现成的两个不够 |
| 单次超时 | ≤ 20 秒，超时必须降级 | 不允许用户无限等待 |
| 降级路径 | 必须存在（退回 B） | 智能层挂了页面不能变砖 |

### 3.2 智能层放哪里（需要她拍板，我给倾向）

| 选项 | 成本 | 复杂度 | 我的倾向 |
|---|---|---|---|
| 阿里云函数计算 FC | 按调用计费，可能有免费额度 | 新增一个云产品要管 | 若调用量小、想少维护，选这个 |
| 她现有 ECS 上的一个 loopback 小服务 | 0 新增费用 | 一个进程 + 一个 nginx 位置，符合她已有的"多项目隔离"基线 | **倾向这个**（她已有 ECS、已有证书体系、已有 PM2 基线，不新增云产品） |
| 大陆境外主机 | 低 | 需另购 | 不推荐（大陆访问不稳） |

## 4. 误指路怎么压下去（这是 C 成败的关键）

四条硬机制，写进系统提示与输出契约：

1. **信息不足必须反问**：输出里先给"仍需知道什么"字段；缺关键事实时**不允许给默认路径**。
2. **每条资源必须带来源 URL**：没有可点开来源的资源，不允许出现在输出里。
3. **必须标"无法核实"**：模型不确定时输出"我查不到可靠来源"，页面照实显示（不许润色成确定语气）。
4. **时间敏感声明**：法规、政策、价格类结论必须带"以官方最新为准"的提示与查证入口。

## 5. 旧约束：保留 / 解除

**保留**：单页极简 UI 与渐进披露、移动优先与无障碍基线、无账号 / 无社区 / 无埋点、
内容诚信与如实标注、"可以直接跳出去"、不造轮子与复用优先级、每轮 commit + push。

**解除（降级为默认偏好，不再是最高原则）**：
"0 后端 / 0 外部请求 / 纯静态"、"资源与步骤只换数据对象、骨架不动"（已撤销）、
7 个目标按钮的信息架构。

**待定（需她拍板）**：反馈是否仍只存 localStorage。零前端成本，但拿不到统计意义的真实反馈；
若引入轻量回收，会触及"不埋点"原则 → 必须由用户显式动作触发。

## 6. 成本模型（真实数字，来源见文末）

单次闭环的粗估：理解 + 1 次搜索 + 1 次结构化生成 ≈ 输入 3k / 输出 1k tokens + 1 次搜索。

| 项 | 单价 | 单次成本 |
|---|---|---|
| 模型（百炼 qwen-flash 级 / DeepSeek flash 级） | 未命中输入 1–2 元/百万、输出 4–8 元/百万 | ≈ 0.005–0.01 元 |
| 搜索（阿里云联网搜索，标准版阶梯） | 30–42 元/千次 | ≈ 0.03–0.042 元 |
| 搜索（博查） | 约 0.036 元/次（第三方文档，**官方价目未取到**） | ≈ 0.036 元 |
| **合计** | | **≈ 0.02–0.06 元/次** |

- 起步期（每天几十次）→ **每月几元**。
- 1000 次 → **约 20–60 元**。
- **百炼免费额度**：北京地域每模型约 100 万 Token、独立不共享、有效期 90 天（2025-09-08 后开通者）
  → **Step 1 的验证可以做到 0 元**。搜索 API **未标注免费额度**，这是第一笔必然支出。
- 费用敏感提示：搜索按次计费，**必须设每日调用上限**，避免被刷。

## 7. 隐私与合规

意图可能非常私密（邻里纠纷、家庭矛盾、老人失能、换工作）。因此：

- **页面必须直说**：意图会离开浏览器、发往哪个平台、我们是否留存。
- **默认不留存原文**：只在用户显式点击"把这句话发回给我"时才带走文本。
- **不记日志正文**：接口侧只记录错误码与耗时，不记录用户输入。
- ⚠️ 涉及个人信息处理，具体合规口径**需专业复核**，本文件不代替法律意见。
- ⚠️ 一旦页面开始输出"建议"，内容责任面会变化，需与备案主体一致（四个域名均已备案，但**备案主体性质与经营性内容**要单独确认）。

## 8. 下一最小实验（Step 1，不写代码、不部署）

**目标**：在花任何开发成本之前，先确认"现成能力能不能过及格线"。

1. 用**扣子个人版或百炼应用**（零代码）搭一个智能体，提示词按 §4 的四条硬机制写死；
2. 把压力集 S1–S6 的六句原话逐条灌进去；
3. 对每条输出逐项判定：

| 判据 | 通过标准 |
|---|---|
| (a) 缺事实时是否反问 | 6/6 场景至少问出 1 个**关键**问题（对照压力集"必须询问"列） |
| (b) 每条资源是否可点开 | 6/6 场景所有资源都有真实 URL |
| **(c) 是否出现不存在 / 已失效 / 查不到的东西** | **任一场景踩中 → 该配置直接不通过** |
| (d) 是否把 AI 工具当唯一资源类型 | ≥4/6 场景给出非 AI 资源（机构 / 人 / 政府入口） |
| (e) 第一步是否"今天就能做" | ≥4/6 场景给出可当天执行的动作 |

4. **成本 0 元，人工约 2 小时**；结论写回本文件（不改代码）。

**判定结果怎么用**：

- (a)(b)(c) 全过 → 可能连接口都不用写，直接走 D1 内嵌；
- (c) 踩中或 (b) 不达标 → 按 §3 写 C 的**一个**接口（≤200 行），前端只换数据来源。

**本步明确不做**：不写接口、不改 `web/index.html`、不部署、不动 main、不新增云产品。

## 9. 最大风险

1. **误指路（最大）**：生成式系统会自信地编造机构、政策与门槛。压力集已经证实此类风险真实存在
   （噪声法已被法典吸收、网上流传的"老年友好名单"查不到官方来源、"包就业"话术无人认领）。
   → 它直接摧毁产品唯一的价值主张，所以宁可少说，不可说错。
2. **额度与行为漂移**：免费额度 90 天到期、模型换代、搜索源限流 → 产品行为会在无通知的情况下变化。
   → 必须有降级路径与"当前不可用"的如实提示。
3. **隐私信任**：第一次让用户把私密的话交给一个陌生接口，是一次信任跳跃；处理不好再无第二次。
4. **自己长成平台**：极薄层天然有膨胀倾向（加缓存、加记忆、加第二个接口）。§3.1 的量化边界是护栏。

## 10. 需要她拍板的三件事

1. 智能层放**函数计算**还是**她现有 ECS**（我倾向 ECS，不新增云产品）；
2. 是否接受"意图文本离开浏览器交给第三方模型"（可接受 → C/D1 成立；不接受 → 只剩 A/B，方向要重估）；
3. 搜索调用**每日上限**与月度预算上限（建议先设每天 200 次、每月 50 元封顶）。
