# NORTH STAR — V2 产品内核（冻结）

> 状态：**已冻结**（2026-09-12 Founder Review #1）。
> 本文件是 V2 的唯一产品内核定义。`docs/design/CURRENT_DESIGN.md` 描述的是线上现行版本（V1），
> `docs/loop/MINIMAL_LOOP.md` 描述的是 Prototype 0，两者均**不构成本文件的约束**。

---

## 1. 内核：一条认知链，不是一堆按钮

```
真实意图
  → 理解现实（这个人真正要做成什么、现实条件与风险是什么）
  → 寻找世界（世界里已经存在什么能帮到他）
  → 选择最低阻力且可靠的路径
  → 下一步行动（今天就能做的第一步）
  → 世界真实反馈（他去做，世界返回结果）
  → 调整下一步
```

**注意：这是系统认知链，不是 UI 步骤。**

- UI 仍应保持极简：一屏一件事、移动优先、不摆长表单。
- 但"极简 UI"不允许成为"简化认知"的借口：链上的每一环都必须**在系统内部真实发生**，
  发生不了的时候，必须**如实说"我现在还判断不了"**，而不是给一个看起来对的答案。
- "世界"不等于互联网，更不等于 AI 工具。世界包括：官方机构 / 政府与政策入口 / 企业 /
  医院 / 学校 / 服务商 / 地图与地点 / 法律与调解入口 / 真人（包括用户身边的人）/
  社区 / 开源项目 / 商品与服务 / 数据 / AI / 软件工具 / 现实行动入口。

## 2. 最高原则（按优先级，冲突时上面的赢）

1. **不造轮子**：不自研 Agent Runtime / Workflow Engine / Browser Agent / Coding Agent /
   Search Engine / Sandbox / MCP 平台 / Tool Marketplace。引入任何能力按
   `直接引用 → 官方模板 → API/SDK → 极薄适配层 → 轻度 Fork → 自研（最后选项）` 决策。
2. **优先使用世界已有成熟能力**：模型、搜索、地图、机构入口，能用别人成熟的就用别人的。
3. **Reality > Doctrine**：任何"应该怎样"的设计教条，遇到真实世界的行为数据就作废。
4. **不假装知道**：系统没核实过的东西，不许以确定语气说出来。事实不足时必须反问。
5. **人决定，机器承担复杂性**：把判断和比较的复杂度放在系统这一侧，让用户只需要**决定**。

## 3. 三条明令禁止

1. **禁止用关键词词典猜意图。**
   2026-09-11 typed-door 实证：自调词典 + 15 条查询 → 10 对 / 1 误指路 / 4 未命中。
   对"替人判断"的产品，**误指路是最坏失败**——比"没帮上忙"坏得多。此路永久关闭。
2. **禁止把单一场景硬编码进数据对象后，宣称闭环成立。**
   一个场景跑得通，只证明那个场景能跑通，不证明产品模型成立。
3. **禁止为了守住"纯静态"而制造假的理解。**
   V1 的"0 后端 / 0 外部请求"是那一版的实现选择，**不是 V2 的最高原则**。
   如果理解开放意图 / 访问当前现实 / 核验来源必须要有模型、搜索或 API，就用成熟现成能力。

## 4. 硬约束（仍然不可协商）

| 约束 | 含义 |
|---|---|
| 误指路是最坏失败 | 宁可说"我还判断不了"，不可给一个查不到、不存在、已失效的资源 |
| 内容诚信 | 不虚构资源、机构、价格、门槛、维护状态；引用必须能点开 |
| 可直接跳出去 | 不为留存强迫用户留在页面；成功是"用户真的去做了" |
| 隐私如实 | 意图可能很私密（家庭矛盾、法律问题）。数据出不出浏览器、去哪里，必须在页面上说清楚 |
| 无账号、无社区、无埋点统计 | 不做用户系统，不做社区，不做行为追踪 |
| 移动优先 | 手机是主要入口；触控 ≥44px、对比度达 WCAG AA、320px 起不横向溢出 |
| 每轮 commit + push | 见 `AGENTS.md` §7 |

## 5. 旧约束的保留 / 解除清单

| 旧约束 | 处置 | 理由 |
|---|---|---|
| 单页极简 UI、手风琴渐进披露 | **保留** | 与"认知链 ≠ UI 步骤"不冲突，仍然是正确的呈现方式 |
| 移动优先、无障碍基线、复制回退 | **保留** | 与架构无关的体验底线 |
| 无账号 / 无社区 / 无埋点 | **保留** | 产品定位决定 |
| 内容诚信、如实标注限制 | **保留** | 产品唯一的信任来源 |
| "可以直接跳出去" | **保留** | 成功判据是用户去做了，不是用户留着 |
| `0 后端 / 0 外部请求 / 纯静态` | **解除（降级为默认偏好）** | 只能在"不影响认知链真实性"的前提下守住；守不住就让路 |
| "资源与步骤只换 LOOP 数据对象，骨架逻辑不动" | **撤销** | Prototype 0 的骨架只是原型，不是冻结契约；禁止迁就已写的代码 |
| 7 个目标按钮的信息架构 | **替换** | 目录式入口不承载"理解现实"这一环；但 V1 已核证的工具与限制**作为资源库素材保留复用** |
| 反馈只存 localStorage、靠用户手动复制带回 | **待定** | 零后端可行，但拿不到统计意义上的真实反馈；见 `ARCHITECTURE_DECISION.md` §6 |

## 6. 成功判据 / 失败判据

**成立的样子**：一个真实的人带着一个模糊的真实意图进来，系统给出的路径让他**当天真的做了一个动作**
（打了一个电话、开了一个网页、提交了一份材料、问了一个具体问题），并且他回来时能说出"发生了什么"。

**不成立的样子（任一即失败）**：

- 系统给了一个**不存在 / 已失效 / 查不到来源**的资源；
- 系统在事实不足时**不反问**，而是自己补全了假设；
- 用户照做后**世界没有任何回应**，且系统没有预警这种可能；
- 用户做完之后，系统**无法据此调整下一步**（即闭环断在最后一环）。
