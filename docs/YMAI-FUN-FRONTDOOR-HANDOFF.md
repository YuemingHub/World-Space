# ymai.fun 的门面页为什么还没上线（交接给能改后端的人）

日期：2026-09-20 · 提出方：前端/部署会话 · **我没有改任何后端代码，也没动 nginx**

## 一句话

统一设计轮做的 `web/index.html` 在 `main` 这条线上；
**线上 ymai.fun 跑的是 `v2` 分支，静态根是 `web/v2/`，我改的那个文件根本不在服务路径上。**
所以"把新门面发上去"不是发布动作，是一个产品决定：`/` 到底给谁。

## 实测到的事实（都在生产机上取的，不是读文档）

| 项 | 值 |
|---|---|
| 发布根 | `/opt/world-space/releases/e8284c4…/` + `current` 软链 |
| 服务方式 | nginx → upstream `world_space_node` → `127.0.0.1:3200`（`server/world.mjs`，用户 `wsapp`） |
| 静态根 | `world.mjs:70` → `webDir: join(HERE, "..", "web", "v2")` |
| 公网 `GET /` | **302 → `/login`**（`world.mjs:408-410`：未登录或门坏了就去登录页） |
| 公网 `GET /web/index.html` | **404**（因为静态根是 `web/v2`，它会去找 `web/v2/web/index.html`） |
| `v2` 分支的 `web/v2/index.html` | 1335 字节，是个带 `app.js` / `render.mjs` 的应用外壳，不是静态门面页 |
| `main` 这条线的 `web/index.html` | 201 KB，就是统一设计轮做的那张静态门面页（分支 `design/ming-language-20260919`） |
| 两条线的关系 | `git merge-base --is-ancestor origin/v2 HEAD` 不成立 —— 互不包含 |

## 要谁决定什么

**决定：`https://ymai.fun/` 的未登录访客应该看到什么。**

- **A. 门面页给公众，登录后才进应用**（我理解这是"公开表达层统一"的本意）
  需要两处，都在后端侧：
  1. `server/world.mjs:408-410` 那个 `redirect(res, "/login")` 要按"未登录访问 `/`"放行到静态门面页；
  2. 门面页要落到 `webDir` 里能被取到的位置（要么把它放进 `web/v2/`，要么给它一个独立 location）。
  我不做这两条：前者是业务路由，后者会把门面页塞进 v2 应用目录，都不属于前端 UI 范围。
- **B. `ymai.fun` 继续只作登录后的应用**，那么门面页应该换一个域名/子域发布，
  并明确它不在 `ymai.fun` 根路径上。
- **C. 维持现状**：门面页只存在于 `main` 分支，不对外。

## 如果选 A，我这边可以立刻配合的

门面页已经是**单文件、零依赖、零外部请求、字体子集内联**（实测 1 个请求、0 个 JS 报错、
320–1440 无横向溢出、498 个文字元素对比度 0 处不达标），放进任何静态目录都能直接跑。
告诉我最终放在哪个路径、`/` 的放行规则怎么定，我来出文件和校验清单。
