# 行动-现实回路（Reality Return）

> 本文是「打开工具 ≠ 现实已改变」的常设判断记录：回路定义、8 个入口的逐项审计、3 个验收例、以及明确不做的部分。
> 与 PRODUCT.md §8 配套；catalog 的复核语义见 `catalog/resources.json` 的 review_expiry。
> 最后更新：2026-09-25

## 1. 回路定义

一次行动完整的形状是：

```
我想做什么（Intent）
→ 借世界已有能力（Capability）
→ 第一步（First Action）
→ 现实里出现结果（Observable Result）
→ 没结果 / 被卡住 / 说不清（No Result / Blocked / Unknown）
→ 用户回来继续（Return）
```

| 段 | 含义 | V0（纯静态）里落在哪 |
|---|---|---|
| Intent | 用户真实想做成的事 | 首页 7 个目标按钮 + 三步兜底 |
| Capability | 推荐的现成能力（可替换） | 目标面板的默认推荐 + catalog/resources.json |
| First Action | 第一件真实动作（不是"先了解一下"） | 可复制模板句 + 「打开」按钮 |
| Observable Result | 现实里应该看到什么 | 面板结果句 + 检查点（「做到这里」）与完成画面（「这些事你都真的做成了」）清单 |
| No Result / Blocked / Unknown | 失败、卡住、说不清的出口 | 每个面板的「如实说」+ 分支（换路径/换问法/官方渠道） |
| Return | 回来怎么继续 | 「发完后回到这个页面继续下一步」、回首页引导、深链、localStorage 进度 |

静态约束：V0 只允许 UX 语言、路径设计、"回来以后怎么继续"的引导、本地轻状态（localStorage）。禁止为这个回路引入后端、账号、数据库。

## 2. 八个入口逐项审计（2026-09-25）

入口数：7 个目标面板 + 1 条三步兜底（兜底按 3 步拆开审计，故下表 10 行）。

八问：①用户到底想实现什么 ②推荐哪个已有能力 ③为什么选它 ④第一件真实动作是什么 ⑤什么叫"已经开始" ⑥现实里应该看到什么结果 ⑦哪些地方可能失败 ⑧什么时候应该重新核查这个推荐。

| 入口 | 原已回答 | 2026-09-25 动作 | 不改及理由 |
|---|---|---|---|
| 写点东西 | ①-⑤、⑦ | ⑥ 补：改稿句改为「改到它变成一段你真能直接发出去的文字为止」 | — |
| 做个网页 | ①-⑤、⑦ | ⑥ 补（发布分支）：「发布后你会得到一个网址：发给别人，手机点开就能看到你的页面」 | — |
| 查明一件事 | ①-⑤、⑦ | ⑥ 补：「核实完你应该能说清：哪几点已确认、哪几点还不确定」 | — |
| 做一张海报 | ①-④、⑥-⑦（⑤隐含在步骤里） | 无 | ⑥ 随步骤自然可见（「换字换图 → 下载」，下载到手就是结果）；⑦ 已有水印/商用授权如实标注 |
| 整理手机照片 | ①-④、⑥-⑦（⑤隐含在步骤里） | 无 | ⑥ 四个子目标的现实结果就是动作本身（重复照片合并掉、照片存上云、拿到印出来的册子、照片变好看）；⑦ 是全站最厚（会员门槛、丢照片投诉、质量参差） |
| 整理资料 / 处理 PDF | ①-④、⑥-⑦（⑤隐含在步骤里） | 无 | ⑥ 已写在步骤里（「整理成三部分」「点执行」后的成品文件） |
| 提取图片文字 | ①-④、⑥-⑦（⑤隐含在步骤里） | 无 | ⑥ 指令即结果（页面原文「长按那张图片 → 点「提取文字」→ 直接复制、转发」，文字出现在手机上） |
| 兜底 · 步 1 | ①-⑤、⑦ | ⑥ 改检查点：原「它回答了你」→「你手里有了一段 AI 写的初稿」（前者是工具行为，不是结果） | — |
| 兜底 · 步 2 | ①-⑦ | 无 | ⑥ 路径文档已是结果句（step-2-make-it-better：「你手里有一段自己改过、愿意直接用的话」）；页面对应句为「继续提要求，直到那段话你真的愿意用」 |
| 兜底 · 步 3 | ①-⑦ | 无 | ⑥ 完成画面清单「你自己查到了答案，还核实过它靠不靠谱」已达标 |

### 2.1 ⑧「何时重新核查」的落点

⑧ 不写进用户界面（普通人不需要在按钮旁看到复核日期；复核是推荐方的责任），由 catalog 承载：

- 每个资源新增 `review_expiry`（本次复核 2026-09-25 + 90 天 = 2026-12-24）；
- 到期前必须重新核查价格/免费档/可访问性/政策，更新 `last_reviewed_at` 并顺延；
- 面向用户的条件性提醒保留在面板「如实说」里（水印、会员、丢照片投诉、需电脑等）。

### 2.2 没有改的地方，同样是有意的判断

- 海报/照片/整理资料/OCR 四个面板的 ⑤（什么叫"已经开始"）与 ⑥ 均"随步骤自然可见"（如「重复项目 → 合并」「换字换图 → 下载」），加一句统一的结果标语只会变臃肿（违背极简）。
- 全站已有"回来继续"引导（发完后回到这个页面、回首页选真正想做的事、深链可收藏），未新增机制。
- catalog 不加 `expected_first_action` / `observable_result`：这两者按"目标"而不是按"工具"承载（写东西用豆包和整理资料用豆包，第一步与结果都不同）。同一句话只在目标面板维护一处，避免两处漂移。

## 3. 验收例（3 个真实入口）

每个例子按 TOOL_OPENED → ACTION_TAKEN → OBSERVABLE_RESULT → BLOCKED/UNKNOWN 拆开；最后一行为"没结果的样子"（反面对照）。

### 例 1 · 写点东西（豆包）

- TOOL_OPENED：点开 doubao.com——这一步什么也不算。
- ACTION_TAKEN：复制面板模板句、换成自己的事 → 发送 → 回「太正式了」「短一点」改稿。
- OBSERVABLE_RESULT：你手里有一段自己愿意直接发出去/存下来的文字（页面对应：「改到它变成一段你真能直接发出去的文字为止」）。
- BLOCKED / UNKNOWN：提示登录 → 手机号/微信；初稿里的事实（时间、名字、数字）可能是它猜的 → 发出前自己过一遍；改几轮还不满意 → 把要求说具体（给谁看、多长、必须提到什么）。
- 没结果的样子：聊天框里有过一段话，但你没改过、也不打算用——那只是工具回了你，不是做成。

### 例 2 · 做个网页（豆包预览 / v0 发布）

- TOOL_OPENED：打开豆包对话（或 v0）——什么也不算。
- ACTION_TAKEN：发模板句 → 「显示预览」 → 「颜色换成蓝色」；要给别人看 → v0 生成并发布。
- OBSERVABLE_RESULT：豆包路线：屏幕上出现一个真的能看、能改的页面；v0 路线：拿到一个网址，发给别人手机点开就能看到（页面对应：「发布后你会得到一个网址」）。
- BLOCKED / UNKNOWN：只看到代码没预览 → 跟它说「显示预览」；v0 免费额度用完 → 等每天额度或付费；登录、支付、存数据一句话做不出来 → 先做最简单的静态第一版。
- 没结果的样子：对话里"生成过"好几次，但没有任何人能打开看到——还不是网页。

### 例 3 · 查明一件事（DeepSeek）

- TOOL_OPENED：打开 chat.deepseek.com——什么也不算。
- ACTION_TAKEN：开「深度思考 + 联网搜索」→ 大白话提问 → 点来源链接 → 涉及钱/政策/法律去官方渠道再确认（不放心用豆包对问）。
- OBSERVABLE_RESULT：你能说清哪几点已经确认（有来源）、哪几点还不确定（页面对应：「核实完你应该能说清：哪几点已确认、哪几点还不确定」）。
- BLOCKED / UNKNOWN：没有来源可点 → 按未证实处理；两个 AI 答案冲突 → 以官方渠道为准；完全查不到 → 明确记"不确定"，不要硬信。
- 没结果的样子：看完答案说"知道了"，但没点过来源、也说不出哪些不确定——那不是查清楚，只是看过 AI 说话。

## 4. 明确不做（保持薄）

- 无后端、无账号、无数据库、无任务追踪；World Space 不做执行平台。
- 不接 PRK：现在没有 PRK API 调用、没有 PRK 写入路径（边界见 PRODUCT.md §8）。
- 不为"结果"新增 UI 组件（不加结果输入框、不在页面上展示复核日期）——回路靠现有文案、路径与引导承载。
- catalog 不扩成 capability registry：只在有真实产品用途时加字段（本次：known_failure、review_expiry）。
