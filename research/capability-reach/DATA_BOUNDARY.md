# 数据边界（Mission 4）

> 原则一句话：**真人来过的痕迹，默认不进 Git。**
> 这不是合规体系，只是四条能记住的规矩。上位依据：`docs/v2/NORTH_STAR.md` §4.2 隐私决定、
> `docs/CAPABILITY_REACH_LAB.md` §10 Person。

---

## 1. 永远不进仓库

原始资料一律由 **Founder 或参与者本人持有**，仓库只留"必要、脱敏、经过允许的研究摘录"。

| 不进仓库 | 为什么 |
|---|---|
| 原始录音、录像 | 含第三方声音与公司信息，且体积会永久留在 git 历史里 |
| 私人照片、相册导出 | 高敏感，且照片里有地理位置 |
| 手写日记 / 遗物扫描件 | Lab §6 第 4 条场景的核心材料，一旦进 git 无法真正撤回 |
| 聊天记录截图 | 含别人 |
| 公司真实文件（报表、客户表、内部文档） | 不是我们的数据，也可能是他人的商业秘密 |
| 身份信息、手机号、住址、微信号、单位名 | Person 只允许四项最低信息 |
| 任何 key / token / 口令 | 与本实验无关，也不得因为"顺手"进来 |

**git 的特性决定了"以后删掉"不等于消失**：历史提交、fork、镜像（本仓库存在双端同步配置）都会留副本。
所以边界必须设在**写入之前**，不能设在"提交后再清理"。

## 2. 允许进仓库

- `cases/Cxx-Y.md`：按 `TEMPLATE.md` 填的**研究摘录**，其中原话只保留研究必需的那几句；
- 脱敏后的结果描述：例如"合并后 1,248 行、3 个来源表、发现 2 处列名不一致"；
- 我们自己造的 fixture（见 §4）；
- 计数与判定：Reach 状态、Barrier 类型、耗时。

## 3. 证据分两层（2026-09-19 定稿）

旧版有一处自相矛盾：Lab 要求 Path A「AI 回复原文保留」，
而本文件 §1 禁止真人原始内容进公开 Git。分层之后两者不冲突。

### Private Session Evidence

持有人：**参与者本人设备**，或 **Founder 的私有本地空间**。

```text
允许包含：
    完整 AI 对话
    原始文件
    完整 Raw Reality
    操作截图
    必要的结果文件

绝不允许：
    commit
    push
    进入 Git 历史
    进入 CNB 镜像
```

实验结束后不需要的，由持有人直接删除。
**不要因为研究需要去制造一个新的私人数据仓库。**

### Public Research Record

Git 仓库里的那个 Case 文件（本目录 §2 的范围）。

```text
允许：最低人物信息 / 脱敏任务描述 / 原话摘录 ≤25 字 / 耗时 / 行为 /
     Barrier / 结果是否成功 / Verification 事实 / Before-After 与 Next Time 必要摘录

禁止：完整 AI 回复、完整聊天、真实 Excel、照片、录音、手稿、
     公司资料、任何可识别个人的信息
```

**公开 Case 的字段级红线**（逐格执行，不只针对附件）：

```text
真人原话摘录          ≤ 25 字
姓名 / 单位           不得出现
手机号 / 微信号 / 住址  不得出现
真实文件名            不得出现（First Real Result 只写结果类型）
私人 URL / 私人照片路径  不得出现
账号标识              不得出现
真人原始文件           不得上传
```

结果类型怎么写：`生成 1 个合并后的 xlsx` / `生成 1 份转录文本` / `生成 1 个可打开页面`。
确有私人结果文件 → 只留在参与者设备 / Private 层。

### 一句话

```text
完整的东西留在人手里，研究需要的东西才进仓库。
```

若 Founder 选择不保留 Private Evidence：允许，Case 里注明 `RAW_AI_RESPONSE_RETAINED = NO`。

### Wave 1 默认采用最小留存

```text
Private Session Evidence 持有人 = 参与者本人设备
Founder 默认不复制完整 AI 对话
Founder 默认不保存真实原始文件
录音 = NO
```

只有**实验过程中确实需要某份完整内容才能复核**，并且**参与者明确同意**，
Founder 才可临时保留在自己的私有本地空间。

仍然：

```text
NO Git
NO CNB
NO cloud research archive
```

**不因为研究方便建立新的私人数据库。**

## 4. 引用规则

需要指认"他说过这句话"时：

```text
写：他说「……」（≤25 字的必需片段，不含可识别信息）
不写：整段转写、录音文件名、时间戳、说话人真名
```

## 5. Fixture 纪律（Lab §8 / Mission 8）

- fixture 必须**自生成、虚构**：编的销量表、假数字截图、公开无敏感音频、虚构手写页。
- 禁止拿真人文件当"方便测试"的样本，即使当场同意——因为仓库是长期公开的。
- fixture 放 `research/capability-reach/fixtures/`，并在文件头写一行：`本文件为自生成虚构样本，不含任何真实个人数据。`

## 6. 技术上顺手加的那道闸

`.gitignore` 增加了一段**只作用于本目录**的规则：`raw/` 以及录音、照片、PDF、Office 文档等扩展名
（故意不做全局屏蔽，以免影响仓库其他资产），`fixtures/` 例外放行。
目的是**在写入前挡住**，不是替代判断。**被 ignore 不代表可以偷偷提交**：
真要提交任何含个人内容的文件，必须先经 Founder 明确同意。

## 7. 明说的未决

本文件只立边界，不解决这三件（都在等 Founder）：

1. 谁持有 Private Session Evidence（参与者自己手机？Founder 本机？），以及允许留存多久；
2. 是否录音——Wave 1 **先不录音**（见 `WAVE1-PACK.md` §3），靠参与者自己写 Raw Reality；
   若将来证明必须录音，单独决策，且录音只归 Private 层；
3. 参与者要不要一份看得懂的说明（我们用他什么数据、留多久、怎么退出）
   ——**已解决**：见 [`PARTICIPANT-NOTICE.md`](PARTICIPANT-NOTICE.md)，用普通话写的，
   参加前给参与者看。Lab §19-3 的原始问题即此条。
