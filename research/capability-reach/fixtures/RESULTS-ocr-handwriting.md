# Fixture C · 虚构手写页 → OCR / 转录

> 全虚构，无真实个人数据（`DATA_BOUNDARY.md` §4）。
> 脚本 `make_fixture_c_handwriting.py` 可本地重跑；原始输出在 `out/fixture_c_ocr_output.txt`。

---

## 0. 先说一个诚实的局限

本机**没有手写字体**，所以用「楷体 + 逐字抖动（每字随机旋转 ±6°、位置抖动、墨色深浅）」近似
**比较工整的手写**。

```text
这与真实潦草手写仍有差距。
本 fixture 不拿它冒充真手写，结论也不外推到"潦草手写也这样"。
```

## 1. 输入

一页虚构的手写便条（"爸留下的笔记本·第 3 页"），故意埋的易错点：

```text
8/3       "8 月 3 日"、"8,300"、"8 号 3 单元"
0/O 1/l   电话 "l38OOl3lO08"（小写 L 与 1、大写 O 与 0 混排）
日期       1987 年 8 月 3 日（无分隔符，靠上下文断句）
小数点     "l03.50"（少一个点就是 10350）
相似名字   张伟（本页）/ 张玮（Fixture A 里那个人）
语义陷阱   "0 是零，不是字母 O" —— 识别对了反而改变原意
```

两档画质：v1 clean（扫描件级）、v2 photo（手机随手拍，jpeg q55）。

## 2. 能力

与 Fixture A 同一套本地 OCR（rapidocr-onnxruntime，纯离线）。
证据等级同样是 **Machine Evidence**，不是普通人在手机上用的那个能力。

## 3. 错误形态

**v1 clean：**

```text
l03.50         → "103 50"          小数点变成空格（可疑，但看得出）
8,300          → "8300"            逗号丢失（无害）
l38OOl3lO08    → "13800131008"     全对（l→1、O→0 都被纠正）
不是字母 O      → "不是字母0"       语义反转
```

**v2 photo（手机随手拍）：**

```text
l03.50         → "10350"           小数点彻底消失 → 10350
```

## 4. 错误是否显眼

| 错误 | 显眼吗 | 危险程度 |
|---|---|---|
| `103 50` | 显眼 | 低：空格本身就是破绽，会让人回头看原件 |
| `10350` | **不显眼** | 高：完全像一个合法数字，没有任何视觉异常 |
| `13800131008` | 不显眼 | 无：它确实是对的（11 位手机号，全中） |
| `不是字母0` | **不显眼** | 中：句子通顺，但原意被反转了 |

### 最值得记的一条

```text
v1（画质好）：103 50   —— 错，但有破绽
v2（画质差）：10350    —— 错得更彻底，但完全干净
```

**画质越差，错误越没有破绽。** 因为引擎会输出"最可能成立的合法串"，
而"合法"恰恰意味着它不会长得像错的。

`l03.50 → 10350` 差了 100 倍：一百零三元五角，变成一万零三百五十元。

## 5. Verification 方法（普通人现实可行吗）

| 方法 | 能抓到什么 | 可行性 |
|---|---|---|
| 常识 / 量级校验（两袋水泥不可能一万块） | 抓到 `10350` | 可行，但依赖**这个人恰好有这个常识**，且愿意逐条看 |
| 关键数字回读（把识别出的数字念回原件核对） | 全部能抓 | 可行，但要逐条做 |
| 格式校验（手机号 11 位、日期有年月日） | 本例反而没用（手机号全对） | 视字段而定 |
| 合计校验 | **不适用** | 手写便条没有合计行 |

与 Fixture A 的差别：表格有合计可以兜底，**手写便条没有兜底**。
这意味着手写场景的 Verification 完全依赖"人愿不愿意逐条回看"。

## 6. Operator 结论

```text
能力层：TECHNICAL_FEASIBILITY
观察层：OPERATOR_OBSERVATION
```

- **TECHNICAL_FEASIBILITY**：本地 OCR 在模拟手写上读出了全部行，连 `l38OOl3lO08`
  这种刻意混排的 0/O、1/l 都能纠正成正确的 11 位号码。
- **OPERATOR_OBSERVATION**：手写场景的失败方式不是"读不出"，而是
  **"读出来了、通顺、合法、但是错的"**；且没有合计这类结构性兜底。
  普通人唯一现实的 Verification 是逐条回看——而那正是他想省掉的力气。

**不得输出 `ORDINARY_REACHABLE`。**
