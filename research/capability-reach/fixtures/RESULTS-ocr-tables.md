# Fixture A · 虚构数字截图 → OCR / 结构化表格

> 全虚构，无真实个人数据（`DATA_BOUNDARY.md` §4）。
> 脚本 `make_fixture_a_ocr.py` 可本地重跑复核；原始输出在 `out/fixture_a_ocr_output.txt`。

---

## 1. 输入

一张虚构的"九月费用明细"截图，5 行明细 + 1 行合计。故意埋的易错点：

```text
8/3 相邻      8,300.00 与 380.00 同表
0/O           103.50、1,806.00
1/l           1,806.00
日期           09-06 / 09-08 / 09-16 / 09-19 混排
小数点         103.50（少一个点就是 10350）
千分位逗号      1,806.00、8,300.00
相似人名        张伟 / 张玮
合计校验        合计 = 五行之和，任何一行读错都会让合计对不上
```

三档画质，对应三种"图是怎么到用户手里的"：

| 变体 | 模拟什么 |
|---|---|
| v1 clean | 自己电脑上原图截图 |
| v2 jpeg45 | 微信转发之后（微信会重压缩） |
| v3 lowres | 聊天记录里存的缩略图 / 被缩放过的老图 |

## 2. 能力

```text
本地 OCR：rapidocr-onnxruntime 1.2.3（PP-OCR，onnxruntime 1.30），纯离线，无外部请求
环境：本机 Windows，中国大陆电信网络，未调用任何付费 API
```

⚠️ 这不是普通人在手机上会用的那个能力（微信长按提取文字 / iOS 实况文本 / 手机 AI 出表）。
本机无法真机验证那三个，本 fixture 的证据等级是 **Machine Evidence**。

## 3. 错误形态（逐档）

**v1 clean** — 数值全部正确，只有无害噪声：

```text
380.00     → "380. 00"      小数点后插入空格
1,080.00   → "1, 080. 00"   逗号后、小数点后插入空格
金额(元)    → "金额(元）"     半角括号变全角
```

**v2 jpeg45（微信压缩级）** — 出现第一次真正的错误：

```text
8,300.00 → "8.300.00"   千分位逗号被读成小数点
```

**v3 lowres（缩略图）** — 出现更隐蔽的错误：

```text
2026-09-16 → "20260916"   连字符消失
2026-09-06 → "20260906"   连字符消失
2026-09-19 → "20260919"   连字符消失
```

注意：同一列里 `2026-09-08`、`2026-09-01` 的连字符**保留**了。错的只有一部分行。

合计行 `11,669.50` 在三档里都识别正确。

## 4. 错误是否显眼

| 错误 | 显眼吗 | 为什么 |
|---|---|---|
| `380. 00` | 显眼，但无害 | 空格很怪，数值没变 |
| `8.300.00` | 半显眼 | 两个小数点看得出怪；但粘进 Excel 可能变成 8.3，也可能变成文本，不一定报错 |
| `20260916` | **不显眼** | 它像一个合法编号/日期戳。只有跟同列其他行对照，才发现格式不一致 |

`20260916` 是最危险的一类：单看完全合法，混进一列才会让排序、筛选、透视静默错乱。

## 5. Verification 方法（普通人现实可行吗）

| 方法 | 能抓到什么 | 普通人做得到吗 |
|---|---|---|
| 把识别结果粘进表格重算合计，与原图合计比对 | 抓到 v2（差 8291.70） | 做得到，会加法就行 |
| 逐列检查数据格式是不是一致 | 抓到 v3 的日期 | 做得到，但**要想到去看**，这不是本能 |
| 关键单元格与原件逐字比对 | 全都能抓 | 做得到，但这正是用户想省掉的力气 |

关键结论：

> 总额校验只覆盖"金额类"错误，不覆盖"日期 / 格式类"错误。
> 一个只核对合计的人，会把 v3 的错误当成干净结果收下。

## 6. Operator 结论

```text
能力层：TECHNICAL_FEASIBILITY
观察层：OPERATOR_OBSERVATION
```

- **TECHNICAL_FEASIBILITY**：三档画质下本地 OCR 都读出了全部 7 行，字符级可用。
- **OPERATOR_OBSERVATION**：真正的风险不是"读不出来"，是"读出来的东西错了但看起来对"；
  而且**画质越差，错误越干净**（引擎倾向于输出最可能的合法串，反而不留破绽）。

**不得输出 `ORDINARY_REACHABLE`。** 本机跑通 ≠ 普通人跑得通；真机（微信提取 / 手机 AI）本轮未测。
